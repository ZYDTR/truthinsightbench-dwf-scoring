# 阅读器视觉设计合同

## 目标

让界面帮助读者持续阅读，并在需要时发现目录、术语解释和搜索。正文始终拥有最高的持续注意力；交互入口只在读者接近或操作时变得明确。

## 从参考页面提取设计

用户给出参考页面或截图时，先在指定主题下查看真实页面。至少观察页面顶部、正文段落、标题、链接、代码、分隔线和一个浮层或按钮状态。页面很长时不要只依据当前滚动位置下结论。

结合截图与 computed style 记录这些关系：

- 页面最大面积的底色。
- 顶栏、侧栏、提示框、代码块和浮层怎样从底色上分层。
- 标题、正文、辅助文字和禁用文字的灰阶顺序。
- 边框相对背景的可见程度。
- 强调色负责哪些动作，出现频率多高。
- 圆角、阴影、线宽和留白带来的界面性格。

提取设计关系，避免整页复制。参考站可能是窄博客，阅读器需要目录和宽技术正文；保留阅读器的信息结构，只迁移色彩职责、对比强度、表面层次和交互气质。

## 单个主题的色彩语法

一个主题由四类 token 组成：

1. 面积色：page、surface、surface-raised、surface-soft、sidebar。
2. 文字色：ink、ink-soft、muted、faint。
3. 结构色：rule、rule-strong、shadow、overlay。
4. 交互色：accent、accent-strong、accent-soft。

面积色应共享一种冷暖倾向。文字色与结构色从相容的中性色阶产生。强调色只承担链接、焦点、选中、悬浮和阅读进度；它不负责给普通内容铺大面积底色。

改变 `page` 后，逐一审视其他 token。冷白背景换成米黄时，冷灰蓝正文、雾绿侧栏和青色高亮会形成拼接感，需要一起回到暖中性色，再选择一个受控的强调色。

## 当前内置主题

浅色主题采用暖米色系统：

- page `#f7f2e8`
- surface `#fffdf8`
- sidebar `#f1ece2`
- ink `#302f2c`
- ink-soft `#47443f`
- muted `#5f5b54`
- faint `#6b665e`
- rule `#ded7cb`
- accent `#6979c9`

米色负责所有大面积和容器层级，低饱和紫蓝只负责交互。目录、提示框、表格、行内代码和卡片不得混入独立的青绿或冷灰蓝色系。正文 `ink-soft` 对 page 的对比度约为 `8.69:1`；最浅的 `faint` 对 page 仍约为 `5.10:1`。不要为了制造灰阶层次，把长正文或辅助信息压回接近 WCAG AA 下限。

深色主题源自 `yage.ai/result-certainty.html` 的视觉关系：

- page `#0d0f14`
- surface `#12151d`
- surface-raised `#161922`
- ink `#e7e9ef`
- rule `#242936`
- accent `#8298ff`

这一主题的特征是黑蓝底、冷浅灰正文、细灰蓝分隔线、紫蓝交互色和克制阴影。保留这些关系，不复制参考博客的导航、品牌或 680px 正文宽度。

## 术语入口

术语入口是一种“读到时才发现”的可供性。它只提示这里可以展开，不承担重点标注功能。

静止状态：

- 使用正文原色。
- 背景透明。
- 使用 1px 细实线，颜色约为 accent 的 24% 可见度。
- 不增加额外内边距，不改变文字在行内的节奏。

hover、focus 或卡片打开时：

- 线条和文字可以变为 accent-strong。
- 背景继续保持透明。
- 键盘 focus 仍保留清晰的无障碍 outline。

禁止叠加点状下划线、色块高亮、粗边框和文字变色作为常驻状态。术语密集时，这些效果会把正文变成满屏重点标记。

## 布局关系

宽屏保持三段水平关系：页面边缘留白、目录、目录与正文的呼吸区、正文。当前默认：

- 页面 gutter：24–52px。
- 目录宽度：230–300px。
- 目录与正文间距：56–112px。
- 正文上限：1180px，超宽屏 1260px。

目录靠近页面左侧，正文从目录之后自然展开。间距需要大到能把目录与正文识别为两个区域，又不能形成第三块无意义的空白栏。1020px 以下移除桌面目录，使用目录按钮。

## 卡内拓扑

composite 卡的拓扑位于 prose 之前。图只使用当前主题的文字色、结构色和强调色：节点使用 surface-soft，边界使用 rule-strong，方向箭头使用 accent。颜色不承担唯一语义。

节点标签优先使用一至两行普通语言，边标签使用短动词。包围框表示组件属于当前术语，框外节点表示外部对象。不要用多个同色卡片代替边界关系，也不要给每个节点分配装饰性色。

拓扑在卡片窄宽度下保持文字可读。需要时允许图自身横向滚动，不能把整张卡或页面撑出视口。图必须有 caption 和可访问说明；图下 prose 负责解释关键状态变化，不逐字复述图。

## 视觉验收

至少检查一个 1600×1000 桌面视口和一个约 390×844 手机视口。桌面分别查看浅色、深色以及打开一张长机制卡后的状态；手机查看正文、目录入口与底部 sheet。

验收时回答：

- 每个主题是否能用一句话描述唯一的冷暖倾向和唯一的强调色？
- 目录、提示框、代码块和卡片是否像来自同一界面？
- 正文是否先于术语标记被看见？
- 静止术语是否无底色、保持正文原色？
- 目录与正文之间是否有呼吸感，左右面积是否均衡？
- 浅色和深色切换后，所有表面、文字、边框与交互状态是否一起变化？
- 手机是否没有横向溢出，长卡片和表格是否在自身容器滚动？
- composite 卡的拓扑是否先于 prose、节点与边标签可读、边界归属明确？
- 控制台是否无错误？

修改 token、术语样式或布局后，重新生成全部下游 HTML，再执行这组检查。界面提示文字、测试断言和版本标识必须同步更新。
