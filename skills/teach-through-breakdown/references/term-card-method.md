# 术语决策与解释方法

## 正文、卡片与拓扑的分工

正文承担主因果链。读者关闭所有卡片，仍能说清楚对象怎样进入流程、状态在哪里变化、变化为什么触发下一步以及最终由谁保存结果。

卡片只解释当前触发词。它补充该对象的内部组成、状态所有者、相邻关系和边界，不能替正文修补断链。

拓扑只用于结构型术语。它固定组成对象、包围边界和连接方向，让读者先看见关系再读 prose。拓扑不是全文架构图，也不承担正文唯一结论。

## 概念依赖与出场顺序

对每个新术语记录它依赖哪些读者尚未掌握的概念。正文和卡片必须让依赖先于使用点建立。

默认顺序：

```text
具体对象或动作 → 状态变化 → 可观察差异或后果 → 技术名称 → 精确边界
```

三个检查问题：

1. 删除术语名后，读者是否仍能描述发生了什么？
2. 当前句的理解是否要求预读后文或打开另一张卡？
3. 读者能否不用专业词复述这段？

任一答案不合格时，重排概念依赖。不要在术语后增加括号定义，也不要继续引入更多名词解释前一个名词。

## 术语决策账本

账本至少包含：

| 字段 | 含义 |
|---|---|
| term | 当前唯一术语身份 |
| point-of-use | 正文中的唯一触发字符串 |
| mentions | 完全同指、但不生成入口的写法 |
| decision | KEEP、DELETE 或 RELATE |
| relation group | 共同参与哪条机制；不改变卡片身份 |
| structure | atomic 或 composite |
| reader start | 允许假设读者已经知道什么 |
| dependency | 解释前必须先建立的对象 |
| reader outcome | 读完后能够不用术语说明什么 |
| evidence point | 源码、合同、文档或运行证据 |

### KEEP

当删除该词会损失对象身份、状态变化、因果关系、证据强度或边界判断时保留。能帮助读者定位真实执行层的工具名也可以保留，但卡片仍须说明该工具在对象链中的确切位置。

### DELETE

正文普通语言已经完整表达，或者卡片只进行中英互译、重复正文、展示专业性时删除。正文没有自然使用点的词也不生成卡片。

### RELATE

多个独立术语共同参与一条机制时分别保留专属卡，并在账本中加入同一 relation group。正文写出完整关系；每张卡只解释本词及它与相邻对象的连接。

RELATE 不是合并。`eval()`、`no_grad`、gradient 和 optimizer 若都有下划线，就必须拥有四个不同 card key、四个以自身为首要对象的解释。读者不需要靠依次打开四张卡拼装主机制，因为主机制属于正文。

## 专属卡成立条件

一张合格卡同时满足：

- `aliases` 恰好一个元素，并在正文自然 prose 中真实出现。
- 标题明确指向当前唯一解释对象。
- 开头不使用一串未知术语替代解释。
- body 与其他卡不同；互换两张卡的 body 会产生明显错误。
- 在不打开其他卡的情况下可以理解。
- 解释到当前对象的因果闭环后停止，不套固定栏目或统一篇幅。
- 正文已经完整讲过的内容，卡片不重复；正文没讲透的维度，卡片必须补全。读者打开这张卡后，不需要再打开其他卡、搜索其他词或回到正文补读，就能完整回答当前对象是什么、由什么组成、状态归谁、怎样和前后连接、边界在哪里。

完全同指的大小写、空格、翻译或代码写法变体放入 `mentions`。它们参与搜索，不产生下划线。若两个写法的内部结构或状态所有者不同，它们不是 mention，必须分别建卡。

标题、目录、代码围栏和以“原文写法 / 来源写法”开头的清单不算 point of use，也不生成入口。

## 深度由解释负担决定

简单对象在说明对象类型、所在位置和相邻关系后即可停止。承重机制需要继续说明内部状态、变化顺序、成立条件和失败边界。不要用统一字数衡量深度。

功能只能作为结构产生的后果出现。优先回答：

- 它是什么种类的对象？
- 哪些部分组成它？
- 哪个系统持有它的状态？
- 哪些状态可以改变，改变发生在哪里？
- 它和前后对象如何连接？
- 连接断开后，哪些状态保留，哪些状态消失？

## 什么时候必须画拓扑

满足任一条件时，`structure` 应为 `composite`：

- 本体由两个以上重要组成对象共同成立。
- 需要区分内部与外部边界。
- 同一状态在三个以上对象之间传递。
- 存在返回、重试或循环，仅靠从上到下的 prose 容易丢失方向。

composite 卡必须提供 `topology`。最小拓扑包含：

- 2–8 个理解当前术语必需的节点；
- 至少一条带动词的边；
- 当前术语的边界组；
- 必要时标出的外部节点。

节点名称首先描述普通对象，例如“当前执行状态”“决定下一步的代码”。专业名可以在普通对象建立后追加。边的标签写“读取状态”“写回结果”“触发请求”，不能只写“关系”“交互”。

若概念没有内部组成或关键状态传递，标记 `atomic`，不要为了版面装饰画图。

## 已验证的失败模式

| 失败 | 可观察表现 | 修正 |
|---|---|---|
| 聚合卡伪装 | 身份匹配、generation、label 分别有下划线，却打开同一内容 | 分为三个专属卡，关系留在正文 |
| 卡片复制 | 标题不同，body 归一化后相同 | 重写首要解释对象；完全同指的词改为 mentions |
| 术语链 | Runtime 由“进程、执行语义、环境”连续定义 | 先给一次具体状态循环，最后命名 Runtime |
| 缺少拓扑 | 结构型词靠长段串联五六个组成对象 | 增加最小边界、节点和带动词的边 |
| 过度拓扑 | 原子词也画复杂全局架构 | 删除图，只保留对象身份与相邻关系 |
| 导航误承诺 | 标题或来源词表出现下划线 | 只允许自然 prose 产生入口 |
| 卡片补正文 | 关闭卡片后主线无法复述 | 把最小因果链移回正文 |
| 局部修补 | 修一个截图后同类聚合仍遍布全文 | 重做账本和概念依赖，全文重新生成 |
