## 验收原则

完成的含义是读者获得可复述、可追踪、可应用的理解，并且产物在目标阅读界面中可用。写完文件只代表进入验收。

将确定性检查与独立读者判断分开。脚本负责 schema、别名、入口和 HTML 完整性；陌生读者负责理解、语气和因果闭环。

## 正文自包含

关闭全部术语卡，只读 canonical Markdown。读者应能回答：

1. 起点是什么具体对象？
2. 它经过哪些关键变换？
3. 每一步输入和输出是什么？
4. 哪些数字、文件、状态或权限会改变？
5. 为什么这条方法可能有效？
6. 哪些条件下会失效？
7. 哪些结论来自事实，哪些来自案例记录或推断？
8. 人在流程中真正决定什么？

任何核心答案只能通过卡片获得时，先修正文。

## Internal 内容回归

根据 source contract 或 concept ledger 建立逐项回归清单。重点检查：

- 对象链和执行空间保持完整。
- 代码开关、参数更新、文件写入与业务批准没有被混写。
- 命令输入、输出、读取者和过期条件仍在。
- 数字、案例范围和证据强度没有扩张。
- 删除术语模板后没有删除必要技术边界。

报告最终使用 `CONTENT_VERDICT: SHIP` 或 `CONTENT_VERDICT: BLOCK`。

## External 文风与冷读

使用 [随包固定版本的 External prose lint](portable-context.md#external-写作依赖)；从本 Skill 目录运行 `python3 -B scripts/lint_external_prose.py path/to/article.md --fail-on hard`。保留完整 stdout，直到 hard findings 为 0。

再让独立读者只看 canonical External Markdown，不提供 brief、术语卡、预期答案或历史 QA。完成两项测试：

- 判断作者像分享发现的同行，还是讲师、顾问或规范制定者。
- 不使用专业术语，复述引入段和每个一级章节发生了什么。

任一章节无法复述，或全文主要靠定义与清单推进，输出 `TERMINAL_VERDICT: BLOCK`。全部通过才输出 `TERMINAL_VERDICT: SHIP`。

## 术语卡冷读

从 context、mechanism、evidence、lifecycle 等不同负担中抽取至少 8 张卡。读者逐张回答：

- 输入什么？
- 输出什么？
- 哪些数字、文件或状态能改变？
- 为什么需要这一步？
- 前后步骤怎样相接？
- 能力、证据或决定权停在哪里？

同时检查：

- 简单工具卡明显短于承重机制卡，但两者都已因果闭合。
- 每个可点击术语只打开以自身为解释对象的专属卡；相关术语靠正文和卡内相邻关系连成完整机制。
- 抽查任意两个不同下划线，不能打开相同标题或归一化后相同的正文。
- 每张保留卡在该篇正文至少有一个触发入口。
- 逐文 DELETE 的卡没有出现在该篇“全部术语”中。
- 卡片没有固定栏目或机械对照句式。
- 卡片不依赖读者打开另一张卡才能理解；新名词要么属于 reader baseline，要么在当前卡先建立对象再命名。
- 卡片不重复正文已经完整讲过的内容；正文没讲透的维度，卡片必须补全。读者打开这张卡后，不需要再打开其他卡或回到正文补读，就能完整回答当前对象是什么、由什么组成、状态归谁、怎样和前后连接、边界在哪里。

对所有 composite 卡额外检查：

- 拓扑在 prose 之前显示，包含 2–8 个必要节点、至少一条带动词的边和当前术语边界。
- 图中普通语言对象先于专业名称，没有用一组新术语替代解释。
- 图能区分内部组成和外部对象，箭头方向与正文状态变化一致。
- 图下正文解释状态为什么这样移动，不逐字重复节点。

最终使用 `CARD_VERDICT: SHIP` 或 `CARD_VERDICT: BLOCK`。

## 确定性检查

运行 `scripts/validate_explainer_bundle.py`。必须通过：

- JSON 可解析，cards 为对象映射。
- 实际卡片数匹配逐文账本。
- label、单元素 aliases、可选 mentions、structure 与 body 完整。
- composite 卡的 topology schema 完整；manifest 中 topology_terms 全部命中 composite 卡。
- 大小写归一后无跨卡 alias collision。
- 每张保留卡在 Markdown 有 point-of-use alias。
- required、forbidden 和 distinct term group 符合 manifest。
- 不同卡没有重复 body；标题、目录和来源写法清单不会成为 point of use。
- 固定栏目和机械 `不是……而是……` 句式为 0。
- HTML payload 与 JSON 的 key、label、aliases、mentions、structure、topology、body 一致。
- HTML 内嵌 CSS 和 JavaScript，不依赖外部脚本或样式表。

脚本只报告卡片长度的 min、median、max，不用统一字数阈值判断质量。

## HTML 交互检查

通过本地静态服务器打开最终 HTML，至少检查桌面和手机两种尺寸：

- 页面、目录、正文、术语数量正确。
- 目录靠近左侧，正文使用可用空间；目录与正文有 56–112px 响应式呼吸区；宽屏无居中的窄 800px 内容岛。
- 浅色主题的面积色、文字、边框和强调色内部统一；深色主题同样内部统一。
- 用户给出视觉参考时，记录面积色、文字灰阶、结构色和交互色的提取结果，并说明怎样映射到阅读器。
- 静止术语保持正文原色、透明背景和低对比度细实线；没有点状下划线与背景高亮叠加。
- context 卡与 mechanism 卡都能从正文打开。
- 标题、目录和“原文写法 / 来源写法”清单没有术语下划线。
- `身份匹配`、`generation`、`label` 这类同处一条机制链但对象不同的词，分别打开不同标题和不同正文。
- composite 卡先显示拓扑再显示 prose；拓扑节点、边、边界和标签在桌面与手机均可读。
- hover 可以预览，click 可以固定，Escape 可以关闭。
- Tab、Enter、Space 可以完成同样动作。
- “全部术语”可以搜索 label、alias 和 body。
- 手机使用底部 sheet，页面无横向溢出。
- 表格和代码块在自身容器滚动。
- 浏览器控制台无错误。
- 界面提示文字与实际术语样式、主题行为和交互方式一致。

浏览器或本地地址受到权限策略阻断时，保留静态检查结果，并在交付中明确写出未完成真实交互回归。不要把生成器自测描述成浏览器点击通过。

## Verdict 与阻断处理

按顺序处理 Gate：内容正确性先于文风，正文自包含先于卡片下钻，JSON 和入口先于 HTML 交互。

任何 QA 给出 BLOCK 时，先判定问题层级。字段缺失、拼写和单个失效入口等局部确定性错误可以做最小修复；概念依赖颠倒、聚合卡、术语链、教材式定义串或陌生读者无法复述属于结构性错误，必须回到账本和正文进行全文重排，不能以局部补卡代替。修复后重新生成下游产物，并让原 Gate 回归。不能用主 Agent 主观判断覆盖独立冷读的 BLOCK。
