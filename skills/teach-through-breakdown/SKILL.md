# Teach Through Breakdown

## 目标与调用边界

目标是让读者在不预读后文、不依赖术语表的前提下，看见对象、状态与动作怎样连接，然后才获得这些结构的技术名称。完成后的读者能够不用术语复述主因果链，也能在需要时打开一张只解释当前词的专属卡。

这是高成本的全文重构 Skill，只在用户明确点名时调用。不要根据任务内容相似、用户要求“解释到本质”或希望增加术语卡而自动启用。它不负责普通摘要、局部润色、一般 Markdown 转 HTML 或单个问题的即时回答。

## 必读资源与可用能力

每次调用完整读取：

- [术语决策与解释方法](references/term-card-method.md)
- [输出合同](references/output-contract.md)
- [验收合同](references/acceptance-contract.md)

生成或修改 HTML 时，再完整读取 [阅读器视觉设计合同](references/reader-visual-design.md)。

需要核对代码、协议、实现事实或时间敏感信息时，读取 [独立环境的证据与协作约束](references/portable-context.md)。本 Skill 已经吸收 Internal / External Writing 中与教学解释直接相关的约束；完整写作工作流和 External prose lint 的固定版本入口也列在该文件中。

只有用户明确授权 subagent 时才分派；分派前读取 [独立环境的证据与协作约束](references/portable-context.md) 中的子代理边界。没有独立冷读条件时保留未完成 Gate，不能自行声称通过。

## 结果合同

完整交付必须包含：

- canonical Markdown：关闭全部卡片后仍能独立理解主因果链。
- term decision ledger：记录 KEEP、DELETE、RELATE、关系组和每项判断理由。
- cards JSON：一张卡只有一个正文触发词；不同卡拥有不同标题和不同正文。
- 对结构型术语的卡内拓扑：图中包含组成对象、边界和带动词的连接。
- 自包含 HTML：正文入口、卡片、拓扑、目录、搜索和移动端交互均包含在单文件中。
- acceptance 结果：确定性校验与读者冷读分别给出 verdict。

Internal 与 External 可以共享事实和概念身份，但必须分别建立读者起点、正文入口和解释深度。不要把一篇的全局词表复制给另一篇。

## 解释合同：以下均为硬约束

### 先出现结构，再出现名称

吸收 Internal Writing 的概念出场规则。一个新术语首次进入正文前，读者必须已经看见它命名的具体对象、动作、状态变化或可观察后果。默认认知顺序是：

```text
具体对象或动作 → 状态怎样变化 → 变化造成什么差异 → 必要时给出术语名 → 精确边界
```

不能从作者调研结束后的分类体系开场。不能靠在术语后补括号定义修复依赖颠倒。删除英文名后若句子无法说明实际发生了什么，该术语仍在替代解释。

### 不向前借用尚未建立的概念

解释 A 时，不得把读者尚未认识的 B、C、D 当作 A 的定义材料。卡片可以提到相邻术语，但当前卡必须在不打开其他卡的情况下成立。

每张卡的词汇只能来自三类对象：audience contract 已知内容、已经用普通语言建立的对象、在当前卡中先完成解释再命名的对象。读者需要暂停并向后找定义时，概念顺序不合格。

### 一个入口对应一个解释对象

一个带下划线的术语只打开一张以该词为解释对象的专属卡；一张卡也只拥有一个正文触发词。身份匹配、generation 和 label 即使共同参与 Container 身份判断，也必须分别拥有不同 key、标题和正文。

相关术语使用 RELATE 关系组组织正文，不合并交互身份。完全同指的大小写、空格、翻译或代码写法变体可以放入 `mentions`；`mentions` 只用于检索和说明，不生成下划线。

不得复制同一正文后仅替换卡片标题。两张卡如果能够交换正文而不产生明显错误，说明解释对象仍未分开。

### 结构型术语必须有小拓扑

若一个术语的本体由两个以上重要组成对象构成，或其含义依赖对象之间反复发生的状态传递，将该卡标记为 `structure: "composite"`，并提供 `topology`。例如 Runtime 的卡需要显示执行状态、推进规则、模型请求、工具请求以及它们之间的回流。

拓扑必须满足：

- 只画理解当前术语所需的最小节点；不把全文架构塞进卡片。
- 用包围关系表示所属边界，用箭头表示状态、数据或控制的实际移动。
- 每条边使用动词，说明从哪个对象向哪个对象传递什么或触发什么。
- 节点优先使用普通语言对象名。不得依靠一组新的未解释技术词来解释当前词。
- 外部对象明确放在当前术语边界之外；暂不解释的对象可以标为“外部边界，另卡解释”。
- 图下 prose 解释图中发生的关键状态变化，不重复逐字朗读节点。

原子术语使用 `structure: "atomic"`，不为装饰强加拓扑。是否属于结构型术语由对象组成决定，不由卡片篇幅决定。

### 正文先闭合，卡片再下钻

正文承担完整主因果链。卡片承担局部下钻：当前词的对象身份、内部组成、状态所有者、与前后对象的连接、成立条件和边界。关闭全部卡片后，读者仍能回答起点、关键状态变化、执行者、终点和失败传播。

一张卡在一个入口内把当前词解释清楚。读者打开一张卡后，不需要再打开其他卡、搜索其他词或回到正文补读，就能完整回答这张卡负责的对象是什么、由什么组成、状态归谁、怎样和前后连接、边界在哪里。正文已经完整讲过的内容，卡片不重复；正文没讲透的维度，卡片必须补全。

卡片不采用固定三段模板，也不设统一字数。解释在当前对象形成因果闭环后停止。用户要求解释”本质”时，优先回答对象类型、内部结构、状态归属和相邻关系；功能描述只能作为结构产生的后果出现。

### 使用陌生读者标准，而不是教材声

吸收 External Writing 的 concrete carrier 与无术语复述要求。解释从一个真实对象、一次请求、一个文件或一次状态变化展开，不能以术语目录和连续定义推进。作者姿态是把已经查清的结构呈现给同行，不是让读者先背分类。

结构性失败必须全文重排。不能在原结构上多加卡片、补几句定义或修一个截图位置后声称完成。最终冷读者只看 canonical 文本和单张卡，不看 brief、历史讨论或预期答案；他必须能不用专业词复述每节发生了什么。

## 术语决策

候选术语逐文作三种决定：

- KEEP：该词改变读者对对象、状态、因果、证据或边界的理解，并拥有专属卡。
- DELETE：正文普通语言已经足够，卡片没有新增理解。
- RELATE：该词保留专属卡，同时与其他独立术语放入同一机制关系组。

RELATE 只决定正文组织和卡内相邻关系，不允许多个触发词共享一张卡。账本结构与判断问题见 [术语决策与解释方法](references/term-card-method.md)。

## HTML 阅读器合同

使用 `scripts/build_term_card_reader.mjs` 从 canonical Markdown 和 cards JSON 生成 HTML。不要手改生成结果；修改生成器后必须重新生成所有下游 HTML。

阅读器必须满足：

- 标题、目录及“原文写法 / 来源写法”清单不生成术语入口。
- 正文中的一个入口只绑定一个 card key。
- desktop 支持 hover、focus、click 和键盘；mobile 使用底部 sheet。
- composite 卡先显示小拓扑，再显示解释 prose；拓扑和正文共同位于卡片滚动区域。
- 全部术语可搜索 label、唯一触发词、mentions 和 body。
- CSS、JavaScript、卡片与拓扑数据全部内嵌。
- 视觉和响应式要求遵循 [阅读器视觉设计合同](references/reader-visual-design.md)。

## 验收合同

必须同时通过以下结果 Gate：

1. **概念顺序 Gate**：逐句检查首次出现；没有术语早于其对象、动作或后果，也没有向前借用未知概念。
2. **正文闭合 Gate**：关闭所有卡片仍能复述主因果链。
3. **卡片身份 Gate**：一入口一专属卡，无重复标题、重复正文或聚合卡伪装。
4. **拓扑 Gate**：所有标记为 composite 的卡都有合法拓扑；抽查结构型术语没有被错误标为 atomic。
5. **陌生读者 Gate**：读者不用专业术语仍能复述每节和抽查卡；失败时全文重排，不做局部补丁。
6. **HTML Gate**：schema、payload、主题、布局、桌面/手机交互和控制台均通过。

以下命令从本 Skill 目录运行；安装依赖见 [使用说明](README.md)。运行确定性检查：

```bash
node scripts/build_term_card_reader.mjs --self-test
python3 scripts/validate_explainer_bundle.py path/to/bundle_manifest.json
```

脚本通过不等于真实浏览器和陌生读者通过。权限阻断的 Gate 必须明确标为未验证。

## 已验证的失败模式

| 失败 | 可观察表现 | 必须采取的修正 |
|---|---|---|
| 聚合卡伪装 | 多个不同下划线打开相同标题和正文 | 拆分 card key、标题和正文；关系移回正文或 RELATE 组 |
| 复制卡片 | 新增多张卡但只替换标题 | 重新确定每张卡的首要解释对象；完全同指的写法改入 mentions |
| 术语链解释术语 | 为解释 Runtime 连续引入进程、执行语义、环境等未建立名词 | 先展示一次具体状态循环，最后再命名 Runtime |
| 缺少拓扑 | 结构型术语只能靠长段落串联组成对象 | 卡片增加最小节点、边界和带动词的边 |
| 局部修补结构错误 | 只修截图位置，其他聚合卡继续存在 | 回到候选术语和概念依赖，全文重构后重新生成 |
| 标题误承诺 | 标题或来源词表出现下划线，读者以为有新卡 | 生成器排除导航与词表，只允许自然 prose 成为入口 |
| 卡片补正文 | 关闭卡片后主线断裂 | 把最小可用因果关系移回首次出现处 |
| 教材式定义串 | 每节从名称和分类开始，读者只能重复术语 | 改为具体对象与状态变化先到，执行无术语复述测试 |
