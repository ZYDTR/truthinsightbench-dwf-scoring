# 一致且可复现的最终交付

最终报告应让读者从一条主张定位到同一最终版本的原始输入、实际计算和结果。格式服从公共契约，支撑终稿的主侧与子侧源码、机器结果、图和复核记录一起交付。

## 唯一权威版本

每个核心数值和图表引用明确路径及定位信息，例如表的行列、JSON 键或图号。当前结果的生成脚本、参数、种子、样本口径与报告对应；历史文件保留在明确标识的位置，当前复现入口不调用已被替代的生成器。

整合时依据 `working/analysis-state.md` 逐项核对已采纳子结果与报告位置，把当前版本关系同步到最终报告或复现说明。若新旧近似命名文件并存，明确哪个已被替代；声称某文件记录了限制或修正时，实际读取被引用文件确认内容。未采纳结果保留理由，已完成待审或待重核的核心结果不能直接进入终稿。

子任务完成后的最终文件才用于最终整合。若修改计算定义、筛选或图表源码，受影响的下游结果必须重新生成，再据此更新正文；手改正文或机器摘要不能代替重算。只有真实未决差异才并列报告不同结果，且分别注明口径与证据。

## 干净目标目录复现

在当前会话内另建空目标目录，使用保存的最终源码和原始输入执行声明的复现入口。保留原工作目录与旧证据，不删除它们来制造“干净”。可通过输出路径参数或临时项目副本实现，具体方式由任务决定。

复现入口声明依赖、命令顺序、随机种子与目标目录；支持调用独立复核源码重建终稿依赖的复核结果。人工审读记录明确标为审读，不虚构不存在的脚本。复制到 output/ 的源码应能在声明的目录运行，避免仍写死旧会话或 working/ 路径。

保存各阶段真实退出状态和新产物位置。使用 shell 管道时保留计算阶段的错误状态，例如启用 pipefail，不能只取 tail 的成功退出。成功条件是新目录确实生成核心产物，且与终稿采用结果在有理由的容差内一致；仅存在复现命令或在旧产物目录跑过一次不能替代。

## 最终核对

由最终机器结果核对报告的数值、计数、单位、符号、排序与适用范围。检验报告中的“最大”“全部”“独立”“稳健”等限定词是否得到所引用证据支持。机器结果中的 NaN/Infinity 必须定位原因；无法估计时用明确缺失状态及原因，不能伪装为成功估计。

检查图像实际渲染，确认预期面板有数据、标签可读且来自最终源码。若当前工具不能查看图像，记录未验证范围，不能声称已目验。最后运行公共格式校验，保留原始返回。

报告分别说明：已实际执行并核对的内容、尚未覆盖的复现或复核、科学结论的限制。运行成功和格式通过不能代替科学成立。

最终报告的模型口径、对比、单位和不确定性须与实际执行对象一致；此项还需参照 data-design 与 verification 中的语义核验，文件之间一致本身不足以证明定义正确。修正后的核心结论应出现在读者首先看到的摘要、标题和主表，方法附录不能与它们相矛盾。

复现覆盖终稿所依赖的完整证据链，包括后加入并被采纳的子分析、敏感性结果和关键复核；在空目标目录执行完整入口并核对实际新生成文件。尚未覆盖的关键产物明确列出，不能据局部脚本成功声称全部可复现。

## 可重新计算的证据

交付目录保留支撑核心量的实际分析明细及组级汇总，优先使用有清楚列名的CSV/TSV；复杂结构可补充JSON。记录原始行或独立单位ID、条件/分组、实际使用的数值与变换、估计定义/公式、单位及结果定位，使读者不必猜列或从聊天中找分母。明细必须由真实输入生成，不能从报告数值反填；汇总表与明细用途分别标明。

每个核心量能从随附源码和明细独立重建，不能只有p值/效果标签而没有支撑记录。复杂统计模型同时保留完整可执行源码和诊断，不以平面表替代方法。相对路径或显式输入/输出参数应使产物在另一干净目录可运行，不能继续写入旧会话目录。

问题覆盖、竞争解释、分离验证和执行诊断的关键结果进入最终报告及所引用附件。主侧状态文件用于协调；公共格式通过不会替这些科学验收项作结论。
