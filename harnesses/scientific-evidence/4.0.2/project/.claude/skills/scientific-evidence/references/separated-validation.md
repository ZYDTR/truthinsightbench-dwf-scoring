# 分离证据验证

目标是判断一个已形成的规则能否经受未用于形成该规则的证据。验证先明确待检验的主张和泛化对象，再选择真实独立单位；数据设计决定哪些分离是可行的。

以下名称对应不同证据：独立实现复算检查算法/定义；完整重跑检查可复现性；删除样本或改变方法检查敏感性；分别分析各组描述异质性；留出验证要求形成与验证按独立单位分离。子 Agent 身份、不同文件名或不同随机种子不自动产生独立数据。

对声称执行了留出验证的主张，保存可检查的证据：

- 形成/验证成员或完整组ID及生成脚本；用真实独立单位检查零重叠，保留重复测量与嵌套结构。
- 形成集决定的特征处理、模型/估计规则、参数、预测对象与评价定义；在计算该验证组结果之前保存版本、哈希和真实执行顺序。
- 验证集上的实际输出、观测值、适用时的误差/效应与不确定性，以及同口径简单基线。预处理及参数选择不能使用被留出结果。
- 验证失败或相反结果如何影响主张范围。失败也是有效结果，不能只保存成功组。

按真实组做交叉验证时，每折的规则只由该折形成集拟合；报告各折和汇总，说明完整流程是否在各折外层重复，以及调参是否造成泄漏。已看过全部结果再设计的检验标为事后验证；不能补写时间戳或冻结文件冒充前瞻性设计。

只有少数独立组、缺失组合、模型需要未见过的类别参数、或缺少可靠配对身份时，先判断泛化对象是否可识别。可选择适合问题的较简单、可迁移的规则；不能强行用不可估计的模型预测新组。确实无法执行公共要求时，保存设计依据，把相应泛化结论标为未验证；分组描述和敏感性结果可保留，但不更名为留出。

验证证据可以放入现有结果文件，至少能定位：claim_id、validation_type、unit_definition、formation_members、validation_members、rule_source与版本、rule_fixed_before_evaluation的依据、execution_command、result_locator、outcome和对主张的影响。字段名可以调整；单个自报布尔值或空模板不满足证据要求。
