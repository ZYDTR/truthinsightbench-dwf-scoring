# 独立复核与冲突处理

复核要能发现足以改变结论的错误。分别判断算术一致、方法有效和科学解释成立，不把任一项通过推广为全部通过。

独立复算者获得原始输入、待查问题或主张的定义、专属写入目录和验收条件。需要核对数值时可提供报告值；复算代码从原始输入重新编写，不导入或执行被审查的估计、拟合或检验实现。整个流程重跑属于可复现性检查，可以使用原实现，两者分别留证。

根据风险核对关键样本数、单位、筛选、排序、估计值、不确定性、留出或负对照、图表和文字引用。说明比较口径与容差；同时检查样本依赖、分组身份、混杂和检验假设。数据未提供的信息不能从编号或命名自行推定为事实。

复核产物至少保存：原始输入定位、独立脚本与实际命令、复算值、比较值、定义/单位、差异和影响。非有限值、空图、无法重建的数值应明确暴露，不能以脚本退出成功或公共格式校验通过关闭。

主 Agent 等待子任务完成后，亲读最终源码和结果。出现差异时先核对是否在比较同一文件、列、样本集合、单位、公式和版本；“可能因近似方法不同”只是待检验解释。能够定位则记录证据并修正；不能定位则保留分歧，收窄相应结论。不得要求复核者仅为匹配主结果而改实现。

修订会使受影响的复核结论失效。依据变更范围重新执行需要更新的计算或核查，重建下游表、图、摘要，再检查终稿引用；未经重核的项目标记未覆盖。主 Agent 负责明确当前采用哪一版证据，旧版继续留存但不混入当前结论。

机制或检验效能受到质疑时，执行能够区分解释的检查，或明确无法解决。多数 Agent 赞成、同一实现反复运行、全部自报通过均不能替代证据。工具失败时记录未覆盖范围；主侧补做的部分如实标为自检。

关闭差异需要可复查的定位证据：比较双方真实输入、样本、定义、设计矩阵或执行参数，说明哪一个差异足以导致当前结果。未经检查的“近似不同”“协变量不同”只是候选原因。不能为了让数值匹配而忽略方法错误；独立脚本也可能共享同一假设或单位错误。

关键结论至少有与原实现不同路径的语义核验，例如从原始时间单位推导频率单位、从模型实际列验证调整项、从真实独立来源检查有效样本。选取能推翻该主张的检查，不机械凑检查数量。输出应分别说明数值一致、方法有效、解释支持程度。

收到方法性反证后，主 Agent 核对其依据，再决定修正估计、缩小结论或保留分歧。验收时查看受影响的标题、主结果和摘要是否已同步，不能一边承认推断无效一边保留原核心判断。复核自身有缺陷时也须以证据驳回，而非因其身份为复核者就自动采纳。

本轮复核还应对照公开问题覆盖表，检查主体分析是否回答了目标中的比较，而不仅是检查已经写出的发现。读取实际拟合诊断、区间生成函数与分组身份，核对结果标签的语义。验证被称作holdout时，转入 separated-validation.md 检查成员、规则冻结顺序和实际测试结果；仅看到多个组织/状态的结果表不算通过。

对每项验收分别记录通过、失败或未覆盖，并引用原件中的具体定位。审读出一个足以改变结论的问题时，追踪到受影响的量、主张、标题和最终版本；更正标签、追加局限或重新跑同一错误实现不足以关闭方法问题。
