# 主 Agent 的当前事实与产物状态

目标是让主 Agent 在长分析、反馈修订或恢复任务后，仍能辨认已确认的事实、待解决的问题和终稿应采用的产物。此模块只由主 Agent 维护；子 Agent 在自己的专属目录返回结果，由主 Agent 决定采纳。

## 单一入口

在初始定向时建立 `working/analysis-state.md`。保持它是简短的当前状态，不复制原始表格、工具输出、完整聊天或全部历史；详细内容用路径与定位信息引用。文件已有相关内容时合并维护，不再造平行台账。

可采用以下结构，字段按实际任务合并，尚未知的值明确写未知：

```markdown
# 当前分析状态
更新依据：最近已检查的执行/子任务回执；当前交付版本：rN

## 已确认事实
| ID | 定义、单位与支持范围 | 证据路径及定位 | 已检查版本 |

## 分工与未决问题
| 问题/分支 | 执行者与子任务 ID | 输入、独占输出路径 | 状态、依赖或阻点 |

## 结论与权威产物
| 结论 ID | 当前源码/结果及版本 | 复核状态 | 采纳状态及报告位置 |

## 受影响的旧证据
| 变更依据 | 旧版本与替代路径 | 待重算/重核/同步的位置 |
```

版本可以用短修订号加路径、内容哈希或明确执行记录标识，只要能区分前后两次实际结果。状态应区分进行中、已完成待审、已采纳、未采纳、待重核、阻塞；文件存在不等于完成，完成回执不等于结果已采纳。

## 更新与消费

在接受子任务最终交付、发现冲突、改变定义/筛选/计算、更新终稿或接到反馈时，就近更新受影响条目。把主张标为事实需要原始证据；把结果标为已采纳需要读过最终产物并明确报告位置。暂不采用的子结果写明原因，避免读完回执便遗忘。

计算变化后，先把依赖旧结果的主张、图表、摘要及复核标为待重核；重算并核对后再关闭。历史材料保留明确的替代关系，当前报告和复现入口只指向当前版本。若两个结果仍有实质分歧，保留分歧及各自定义，不能为了台账整齐而消除它。

恢复工作时先用此文件确定下一项有界问题，再按定位读取必要原件；记录陈旧或与原件冲突时，以核验后的原件为准并修正记录。最终核对每个核心主张的证据、复核与报告位置，没有未解释的待审结果或冒充有效的旧版本。此文件提供导航，不替代科学分析或公共报告。

核心主张的状态还需区分支持、条件性支持、反驳和未决。方法性反证或比较口径无效时，记录受影响的主结果、标题和摘要位置，直到修正或收窄后的正文与当前证据一致才关闭；仅补写局限不代表完成整合。

将 question-coverage.md 要求的公开问题覆盖表合入此单一入口，标出尚未回答的研究维度。每项关键验证记录类型与执行证据定位；竞争解释和执行异常连接受影响的主张。主侧据此选择下一项有价值的工作，避免报告已经成形就遗忘未完成的公共要求。
