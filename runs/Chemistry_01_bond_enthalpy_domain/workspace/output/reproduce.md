# Reproduction guide

Everything in `output/Result.md` is regenerated by the scripts below from the three files in `data/`.
No network access is used at any point; `data/` is the complete evidence base.

## 1. Environment

Python 3.11.2. The following were installed during the run and are required:

```bash
pip install scipy scikit-learn matplotlib rdkit
```

Already present: `pandas 3.0.5`, `numpy 2.4.6`, `openpyxl 3.0.9`.

Two environment constraints are handled in code rather than worked around silently:

- **`pandas.read_excel` fails.** pandas 3.0.5 requires `openpyxl >= 3.1.5` but 3.0.9 is installed
  (`ImportError: Pandas requires version '3.1.5' or newer of 'openpyxl'`). The workbook is therefore read
  directly through `openpyxl` in `common.load_xlsx()`.
- **`pyarrow` / `fastparquet` are absent**, so the analysis-table cache (`results/analysis_table.csv`) is CSV,
  not Parquet.
- matplotlib has no display; every figure script calls `matplotlib.use("Agg")` before importing `pyplot`.

## 2. Data integrity

Verify the inputs before anything else. All three files must match `data_manifest.json`:

```bash
python3 - <<'EOF'
import json, hashlib, pathlib
man = json.load(open("data_manifest.json"))
for f in man["files"]:
    p = pathlib.Path("data") / f["path"]
    h = hashlib.sha256(p.read_bytes()).hexdigest()
    print(f["path"], h == f["sha256"])
EOF
```

Recorded hashes (`results/ws5_part1_raw.json`):

| File | sha256 |
|---|---|
| `normalized_views/experimental_benchmark.tsv` | `319bf2c88ab47bb2c7f779163ed48cd2f316e6299eeda0b999d924ffe81ad484` |
| `source_data/bde_db_full.csv.gz` | `2ee36d1548d51289e3faa21e1269b9bbb8f3a8975f9b29719e6beae226864cc6` |
| `source_data/experimental_source_tables.xlsx` | `e7c0c73db91d0d097ca8e9f5d6a8edf5cac537a10530d3732fe7738e9e581f08` |

## 3. Build the shared analysis table

`output/analysis/common.py` holds the loaders, the validated bond-class labeler, the statistical helpers and
the derived table. It is the single definition of every analysis unit used in the report.

```bash
cd <project root>
python3 -c "import sys; sys.path.insert(0,'output/analysis'); import common; common.build_analysis_table()"
```

The first call takes **3–6 minutes**, because it parses 419 parent SMILES with RDKit. It then writes
`output/results/analysis_table.csv` plus a `.key` file containing the sha256 of the three inputs. Later calls
load the cache and return in under a second; **changing any input invalidates the cache automatically**.

The labeler inside `common.py` is validated, not assumed: it reproduces the database's own `bond_type` column
on 484,907/484,907 rows (100%) and on 331/331 benchmark rows with a database counterpart. This is necessary
because the benchmark view carries no bond-type column.

> The labeler requires **sanitised** RDKit parsing. With `sanitize=False`, RDKit reports zero radical electrons
> for these open-shell SMILES and the labeler fails.

## 4. Run the analysis, in order

Each script writes one JSON artifact to `output/results/`.

```bash
python3 output/analysis/finding1_coverage.py            # F1 -> results/f1_coverage_boundary.json
python3 output/analysis/size_interaction_test.py        # F2 -> results/size_interaction_test.json
python3 output/analysis/headline_noise_floor.py         # F3 -> results/headline_noise_floor.json
python3 output/analysis/finding4_reference_channel.py   # F4 -> results/f4_reference_channel.json
python3 output/analysis/weak_bond_overshoot_test.py     # F5 -> results/weak_bond_overshoot_test.json
python3 output/analysis/make_figures.py                 # -> figures/summary_findings.png, error_vs_bond_strength.png
python3 output/analysis/build_evidence_index.py         # -> results/evidence_index.json
```

`headline_noise_floor.py` runs a bootstrap and takes ~2–4 minutes; every other script is fast once the cache
exists.

## 5. Parallel workstreams and adversarial verification

The run was executed as parallel workstreams under the `Workflow` tool. Scripts and their raw outputs are kept
as provenance:

| Script | Scope | Outputs |
|---|---|---|
| `output/analysis/workflow_ws1.js` | six independent analysis workstreams (WS1–WS6) | `results/ws1_*.json` … `ws6_*.json`, `figures/ws[1-6]_*.png` |
| `output/analysis/workflow_verify.js` | twelve independent adversarial verifications | `results/verify_*.json` |

Re-run either with `Workflow({scriptPath: "<path>"})`.

**Honest note on the first workflow run.** All six workstream agents completed their analysis and wrote their
artifacts and figures, but the harness could not collect their structured return values (`subagent completed
without calling StructuredOutput`, after retry) because the `general-purpose` agent type does not expose the
`StructuredOutput` tool that the workflow schema required. The workflow therefore reported `0/6 workstreams
completed` while 23 result artifacts existed on disk. Their returns were recovered by reading the agent
transcripts directly and are preserved verbatim in `results/workstream_returns_recovered.json`. The verification
workflow was re-designed to have agents write verdicts to a file instead of relying on the schema channel, and
it completed normally.

## 6. Verifier verdicts

Twelve verifiers each recomputed one headline claim from the raw files with their own scripts and were asked to
refute it. All twelve **confirmed** the numbers; three made corrections that are reflected in `Result.md`:

- `verify_6` **refuted the framing** that the quantum channel is provably at or below the noise floor, because
  the matched-pair difference distribution is strongly non-Gaussian. `headline_noise_floor.py` now recomputes
  the floor under five scale definitions and reports the bounded conclusion.
- `verify_10` found a **sign-convention defect**: conditioned and unconditioned biases were quoted under
  opposite conventions. Corrected; the overshoot shrinks but does not change sign.
- `verify_11` found a **code defect** in a workstream script (`analysis/ws5_het.py`) — a variance-squared slip
  in the pooled within-molecule SD produced a spurious 165.3 kcal/mol. The correct value is **9.965**, the
  erroneous figure is excluded from the report, and the script has been **fixed in place** (the corrected line
  carries a comment recording the defect). Re-running it now yields 9.9654.

Additional defects found and fixed in this run:

- A `"\x00"`-joined string key **silently truncates** under pandas 3.0's `str` dtype (the NUL is dropped),
  merging 28 distinct keys and undercounting unique fragment pairs as 290,636. Tuple keys are used in
  `finding1_coverage.py`; the corrected 290,664 matches the independently computed value.

`output/results/evidence_index.json` maps each registered finding to its analysis source, result artifact,
figure and verification verdict, with sha256 prefixes, and lists any unresolved reference (currently 0 for
analysis and result evidence).
